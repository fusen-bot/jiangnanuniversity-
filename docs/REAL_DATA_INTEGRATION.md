# 历史资料接入与隐私边界

## 资料盘点结论

项目在仓库外对既有编辑部资料进行了只读结构盘点：共约 1,420 个文件、3.12 GB，其中包含 197 个 Excel 工作簿，以及 PDF、图片和旧系统文件。盘点只读取文件类型、工作表名和表头，不把任何业务记录复制到仓库。

识别出的主要结构包括：

- 版面费：稿件编号、收款/状态、核销号、凭证号、发票抬头、税号、邮箱等。
- 作者稿费：稿件、标题、作者、校内外、工号、金额、身份、银行和联行信息等。
- 审稿费：审稿类型、稿件、审稿人、单位、金额、人员匹配、银行信息和校验结果等。
- 人员主数据：在职/退休工号，以及校外收款人员登记字段。
- 退款与发票：到账、核销、开票、联系和后续处理状态。

## 已实现的兼容策略

- 支持 `.xlsx`、`.xls` 和 `.csv`；`.xls` 由 `xlrd` 读取。
- 自动检查前30行，在多个工作表中选择与业务类型匹配度最高的表头。
- 导入时可明确填写工作表名；包含原始总表、校内/校外子表或多个年份时必须人工指定，避免导入派生子集。
- 兼容真实历史别名，例如“稿件号/稿件编号”“审稿人姓名/审稿人”“抬头/发票抬头”“银行账号/银行卡号”等。
- 记录来源工作表和来源行，便于复核时回到原始材料定位。
- 补齐审稿费与稿费的身份、联系方式、银行字段，以及版面费到账和凭证字段。
- 回归测试使用相同表头但全部为虚构值，不使用真实人员或财务记录。

## 数据进入系统的方式

原始资料继续留在机构受控目录。用户在系统“导入批次”中选择需要处理的单个文件，文件经类型、大小和哈希校验后进入受控存储，再由异步任务解析。禁止把历史目录整体复制进 Git 仓库。

生产迁移应按“只读备份 → 小批抽样 → 字段预览 → 异常复核 → 正式批次”的顺序执行。涉及身份证、税号、银行账号、电话和邮箱的列属于受限数据，仅经办人和必要管理员可以访问；只读角色获取脱敏值。

## GitHub 防泄漏

CI 执行 `python scripts/check_repository_safety.py`，阻止 Excel、CSV、Word、PDF、数据库和压缩包等源资料进入版本库，并扫描常见API Key、GitHub Token、私钥、AWS Key和身份证模式。该检查不能替代人工复核，提交前仍须检查暂存文件清单与diff。

## 尚未自动化的边界

- 旧资料中的退款流程已完成字段盘点，但目前仍归入后续独立业务模块，不把它错误塞进三类费用表。
- PDF正文和图片票据不批量上传或做OCR；需要先确定保存期限、授权范围与脱敏规则。
- 银行与身份字段目前依赖数据库/磁盘加密和访问控制；真实生产部署应接入KMS或字段级加密。
